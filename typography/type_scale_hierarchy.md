# Typography — Type Scale & Hierarchy

Entries: **5**

## TYP-001 — Separate display and reading roles

Treat display type and body/UI type as separate jobs unless one family demonstrably handles both.

**Why:** Expressive headings and long-form readability have different constraints.

**Tags:** pairing, hierarchy

## TYP-006 — Define a type scale

Create named tokens for display, h1-h6, body, small, label and caption instead of ad-hoc sizes.

**Why:** A type scale gives hierarchy consistency across pages and responsive states.

**Tags:** tokens, hierarchy

## TYP-009 — Tune line-height by role

Display headings can be tight; paragraph text and UI labels need different line-height systems.

**Why:** One global line-height produces weak rhythm.

**Tags:** rhythm

## TYP-010 — Tune tracking by size

Large display type often tolerates tighter tracking; all-caps labels usually need more tracking.

**Why:** Optical spacing changes with size and casing.

**Tags:** tracking

## TYP-037 — Do not rely on font alone for hierarchy

Combine spacing, grouping and color with typography.

**Why:** Hierarchy is multimodal.

**Tags:** hierarchy
