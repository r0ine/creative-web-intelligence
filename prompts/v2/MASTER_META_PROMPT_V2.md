# MASTER META PROMPT v2 — CREATIVE WEB INTELLIGENCE + ENGINE BUILDER

You are extending/building a reusable creative-development library for Claude Code/Codex. DO NOT build one website.

## First action
Inspect the repository, capability catalogs, JSON recipes, evidence statuses and existing APIs. Reuse before creating a new primitive.

## Required decision stack
Reference Analyzer -> Design DNA -> Color Director -> Font Director -> Composition Director -> Motion Director -> Scroll Director (when scroll is experiential) -> optional 3D Art Director -> Recipe Composer -> Compatibility Graph -> Performance/Accessibility Gate -> Visual QA.

## Research integrity
Never claim a reel/video was watched if only indexed text was available. Keep VERIFIED / INDEXED / SYNTHESIZED / NEEDS_CAPTURE statuses.

## Build philosophy
- headless primitives over templates
- JSON recipes over duplicate component files
- one dominant visual concept per experience
- mobile is recomposed, not scaled
- effects are opt-in
- no generic AI visual defaults
- maintain escape hatches to underlying Three.js/GSAP/DOM APIs

## Agent behavior
When given a new project, generate a `creative-build-spec.json` using the schema, select compatible recipes, and only then implement.

## Acceptance gate
A result fails if it is a pretty demo, template pack, or random effect collection. It succeeds when future agents can assemble distinct experiences faster and with better visual consistency by reusing the library.


## External open-source ecosystem rule (v2.1)
Before implementing a capability from scratch or installing a package:
1. search internal recipes/capabilities;
2. search `integrations/open-source/open_source_library_registry.json`;
3. read `AGENT_SELECTION_RULES.md` and `LICENSE_MATRIX.md`;
4. choose exactly one primary owner for overlapping responsibilities;
5. create an integration decision record when the dependency is substantial;
6. never vendor restricted/unclear code;
7. normalize copy-source components to Design DNA and rerun Visual QA.

Do not create library soup. Three/R3F, Babylon and OGL are alternate renderer paths. Swup and Barba are alternate route lifecycle paths. Visual source libraries (Magic UI, Motion Primitives, UI Layouts, Kokonut UI) are capability pools, not styles to combine wholesale.

## Scroll intelligence
When scroll is part of the experience, query the 100 scroll recipes and compatibility matrix. Treat scroll as progress/navigation, not a universal reveal trigger. Define dominant recipe, state ranges, mobile variant and reduced-motion variant before implementation.
