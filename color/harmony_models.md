# Harmony Models — Practical Web Use

## Monochromatic recipe
1. Pick one hue.
2. Create low-chroma background/surfaces.
3. Use high-contrast neutral text.
4. Use a stronger chroma version of the same hue for CTA or focus.
5. If the design feels flat, vary material/texture/scale before adding another hue.

## Analogous recipe
1. Pick the dominant hue.
2. Move roughly 20–45° around the wheel for supporting hue families.
3. Keep the support colors lower in area or chroma.
4. Use neutrals to stop the page becoming a rainbow.
5. Good for atmosphere and gradient transitions when transitions have meaning.

## Complementary recipe
1. Pick a dominant hue.
2. Use its opposite family for one high-value contrast role.
3. Do not use both at maximum chroma over large areas.
4. Prefer one vivid + one muted, or one dark + one bright.
5. Validate text separately; visual harmony does not guarantee readable contrast.

## Split-complementary recipe
1. Base hue owns the environment.
2. Two opposite-adjacent hues are supporting accents.
3. Promote only one of the supporting hues to primary CTA.
4. Use the third for secondary data, illustration or subtle 3D lighting.

## Triadic recipe
1. Choose one dominant hue.
2. Choose one secondary hue.
3. Keep the third sparse.
4. Reduce chroma before reducing opacity.
5. Great for playful identity; risky for dense application UI.

## Double-complementary / tetradic
Use rarely in product UI. It is better suited to art direction, illustration and data-rich systems where each family has a clear semantic role. If four hue families have no separate jobs, remove some.
