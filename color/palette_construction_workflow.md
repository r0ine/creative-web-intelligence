# Palette Construction Workflow for Claude/Codex

When asked to design a site, do not immediately choose colors.

## Stage A — classify
Return internal labels:
- `mode`: light | dark | adaptive
- `density`: sparse | editorial | dense-ui
- `visual_driver`: type | image | 3d | data | illustration
- `energy`: restrained | balanced | expressive
- `temperature`: warm | neutral | cool | mixed
- `brand_hue`: known | inferred | none

## Stage B — choose strategy
Pick one:
- neutral + single accent
- monochromatic
- analogous
- complementary
- split-complementary
- triadic
- image-derived
- model/material-derived

## Stage C — assign roles
Build role tokens before decorative swatches.

## Stage D — validate
- text/background contrast
- UI component contrast
- focus visibility
- color-blind/state redundancy
- dark/light parity

## Stage E — explain
For each palette explain:
1. hierarchy
2. mood
3. area ratio
4. interaction roles
5. 3D/imagery relationship
6. accessibility limitations

## Stage F — reject generic defaults
Reject the palette if it only exists because:
- "AI products use purple"
- "luxury uses black and gold"
- "eco uses green"
- "finance uses navy"
- "gaming uses neon"

Category stereotypes may be used only when they are deliberately reinterpreted for the project.
